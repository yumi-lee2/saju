# UX Design Specification saju

**Author:** Soobinlee
**Date:** 2026-08-22

---

## Executive Summary

### Project Vision

saju는 "절대적 존재"가 "너는 지금 이 웹소설에 빙의했다"고 선언하며, 사용자의 생년월일시를 60가지 웹소설풍 캐릭터 중 하나로 리빌해주는 공유형 웹 서비스입니다. 다크 에픽 톤(밤하늘·금박, 신비롭고 극적인 선언)으로 캐릭터를 보여주고, 친구를 초대해 궁합 순위를 만들며, 이 전체 경험이 X(트위터)에서 캡처·공유되며 바이럴을 타는 것이 핵심 목표입니다.

### Target Users

X(트위터)에서 활발히 활동하는 10~30대. MBTI·타로 콘텐츠에 익숙하고 익명으로 공유하는 문화에 편안함을 느낍니다. 대부분 친구의 공유 게시물을 보고 궁금해서 유입되며, 로그인이나 회원가입 없이 즉시 자신의 결과를 확인하고 싶어합니다. 한 번의 방문으로 목적(캐릭터 확인+공유)을 달성해도 충분하며, 재방문을 강제하지 않아도 되는 사용자입니다.

### Key Design Challenges

- **온보딩 마찰 최소화**: 로그인 없이 생년월일시 입력만으로 빠르게 결과에 도달해야 바이럴 유입이 끊기지 않습니다.
- **한 화면에 담긴 정보 위계**: "내 캐릭터 결과 + 친구 궁합 순위 + 공유 버튼"이 한 화면에 공존해야 하는데, 캐릭터 리빌이 주인공이고 순위는 보조 역할이라는 위계를 명확히 해야 합니다.
- **하단 탭바와 "단발성" 원칙의 균형**: 탭바(사주 등록 / 캐릭터 세계관)는 "재방문 앱" 구조인데, 브리프의 "재방문을 강제하지 않는다"는 원칙과 자연스럽게 공존시켜야 합니다.
- **무거운 톤 vs 가벼운 바이럴 인터랙션**: 다크 에픽한 "선언" 연출과 빠르게 캡처·공유하고 싶은 가벼운 UX 사이의 균형이 필요합니다.

### Design Opportunities

- **리빌 모먼트를 캡처 포인트로**: "절대적 존재의 선언" 연출(등장 화면 A안)을 로딩/리빌 시퀀스에 활용해, 결과가 뜨는 순간 자체를 스크린샷하고 싶게 만들 수 있습니다.
- **"캐릭터 세계관" 탭을 재방문 훅으로**: 단발성 경험은 유지하되, 세계관 탭에서 다른 59개 캐릭터나 궁합 유형을 구경하는 것 자체가 재미 요소가 되어 자연스러운 재방문 동기를 만들 수 있습니다.

## Core User Experience

### Defining Experience

가장 중요하고 자주 일어나는 핵심 행동은 **생년월일시 입력 → 캐릭터 리빌 확인 → 공유**입니다. 이 한 번의 흐름이 완벽해야 바이럴 루프가 작동합니다. 결과 화면에는 내 캐릭터, 친구 순위, 공유 버튼이 함께 있지만 "내 캐릭터를 처음 마주하는 순간"이 절대적으로 잘 되어야 하는 상호작용입니다.

### Platform Strategy

모바일 웹 우선(반응형), 터치 기반 인터랙션. 앱 설치나 로그인 없이 링크 클릭 즉시 접근 가능해야 하며, 오프라인 대응은 불필요합니다. X(트위터)에서 링크를 열었을 때 첫 화면부터 완결된 경험을 제공하는 게 핵심입니다.

### Effortless Interactions

- 생년월일시 입력은 최소 클릭·최소 필드로 (별도 회원가입/이메일 없음)
- 결과 화면에서 공유는 원터치 (캡처하기 좋은 레이아웃 + 공유 버튼 동시 제공)
- 친구 초대는 링크 하나로 끝나야 하며, 초대받은 사람도 동일하게 마찰 없는 입력→결과 흐름을 거침

### Critical Success Moments

- **캐릭터 리빌의 순간**: "절대적 존재"의 선언 연출 직후 캐릭터가 드러나는 그 찰나 — 여기서 감탄이 나오지 않으면 공유로 이어지지 않습니다.
- **친구 순위에서 궁합 결과를 확인하는 순간**: 이름 붙은 궁합 유형이 뜨는 순간이 두 번째 감탄 포인트입니다.
- **공유 버튼을 누르는 순간**: 여기까지 마찰 없이 도달해야 바이럴 루프가 완성됩니다.
- 반대로, 입력 단계에서 이탈하거나 결과가 밋밋하게 느껴지면 전체 경험이 실패합니다.

### Experience Principles

- **입력은 짧게, 리빌은 길게** — 정보 입력의 마찰은 극도로 줄이고, 그렇게 아낀 시간과 주의를 캐릭터 리빌 연출에 투자합니다.
- **한 화면, 한 주인공** — 결과 화면은 "내 캐릭터 확인"이 주인공이고, 친구 순위와 공유 버튼은 그 아래를 받치는 보조 동선입니다.
- **로그인 없는 즉시성** — 링크를 열자마자 결과에 도달할 수 있어야 합니다.
- **다시 오고 싶게, 강제로 부르지 않게** — 탭바(사주 등록 / 캐릭터 세계관)는 존재하되, 알림이나 강제 재방문 장치 없이 궁금할 때 스스로 돌아오게 만듭니다.

## Desired Emotional Response

### Primary Emotional Goals

핵심 감정은 **경외감(awe)과 설렘**입니다 — "절대적 존재"가 나만을 위해 선언하는 순간, 사용자는 마치 자신이 특별히 선택받은 듯한 기분을 느껴야 합니다. 이 감정이 친구에게 "이거 해봐"라고 말하게 만드는 원동력입니다.

### Emotional Journey Mapping

- **발견(Discovery)**: 호기심 — 친구가 공유한 캐릭터를 보고 "나도 궁금하다"는 가벼운 끌림
- **입력(Input)**: 기대감 — 부담 없이, 살짝 설레는 마음으로 생년월일시 입력
- **리빌(Reveal)**: 경외감·감탄 — "절대적 존재"의 선언 직후 캐릭터가 드러나는 순간, 압도되는 느낌
- **궁합 확인(Ranking)**: 재미·안도 또는 웃음 — 잘 맞으면 설렘, 안 맞아도 유쾌한 코칭 덕분에 실망이 아니라 웃음으로 전환
- **공유(Share)**: 자부심·소속감 — "내 캐릭터"를 자랑하고 싶은 마음, 친구들과 같은 세계관을 공유한다는 소속감
- **재방문(Return)**: 가벼운 호기심 — 강요당하는 느낌 없이, 궁금할 때 스스로 다시 찾아오는 감정

### Micro-Emotions

- **확신 > 혼란**: 입력 단계에서 뭘 해야 할지 절대 헷갈리지 않아야 함 (개인정보 우려도 없어야 함)
- **설렘 > 불안**: 리빌 직전 로딩/연출이 긴장감을 주되, 불쾌한 불안이 아니라 기분 좋은 기대감이어야 함
- **감탄 > 단순 만족**: 결과가 "괜찮네" 수준이 아니라 "와" 하고 감탄하게 만들어야 공유로 이어짐
- **소속감 > 소외감**: 궁합이 안 좋게 나와도 놀림받는 느낌이 아니라 같이 웃을 수 있는 소속감을 유지해야 함

### Design Implications

- **확신 → 리빌 UX**: 절대적 존재의 선언 → 캐릭터 리빌 사이에 짧은 서스펜스 연출(암전, 별빛, 텍스트 타이핑 등)을 넣어 경외감을 극대화합니다.
- **설렘 → 입력 폼**: 필드를 최소화하고, 입력 중에도 "당신의 사주를 읽는 중..." 같은 분위기 있는 마이크로카피로 기대감을 유지합니다.
- **소속감 → 궁합 코칭 톤**: 안 맞는 궁합에도 유머러스하고 다정한 코칭 문구를 써서, "우리는 안 맞아" 대신 "이렇게 하면 재밌게 지낼 수 있어"로 프레이밍합니다.
- **자부심 → 결과 비주얼**: 공유했을 때 자랑스러울 만큼 완성도 있는 카드형 결과 디자인(다크 에픽 톤)을 유지합니다.

### Emotional Design Principles

- **선택받은 느낌을 설계한다** — 모든 카피와 연출은 "당신만을 위한 선언"이라는 느낌을 유지합니다.
- **실망을 웃음으로 흡수한다** — 부정적인 결과(안 맞는 궁합)조차 유머로 전환해 소속감을 지킵니다.
- **긴장은 짧게, 보상은 크게** — 리빌 직전 서스펜스는 짧게, 리빌 자체는 확실한 임팩트로 보상합니다.
- **강요하지 않는다** — 재방문을 유도하는 알림이나 압박 없이, 스스로 다시 찾아오고 싶게 만듭니다.

## UX Pattern Analysis & Inspiration

### Inspiring Products Analysis

**네이버웹툰**: 캐릭터 중심의 몰입감 있는 커버 아트로 취향을 저격하고, 세로 스크롤과 "다음 화" 넘김으로 자연스러운 정주행을 유도합니다. 별점·댓글 같은 가벼운 반응 장치로 커뮤니티 참여를 이끕니다.

**카카오페이지**: "기다리면 무료" 같은 시간 기반 잠금 해제로 습관적 재방문을 만들고, 랭킹/인기차트로 발견성을 높입니다.

**도령앱**: 최소 입력으로 빠르게 결과에 도달하고, 캡처하기 좋은 결과 카드로 친구 공유 중심 바이럴을 만듭니다. (다만 앞서 파악했듯 단발성 이후 이어지는 게 없다는 한계가 있습니다.)

**점신**: 카드형 UI와 귀여운 마스코트가 안내하는 친근한 톤, 매일 체크인하는 일일 운세로 습관 루프를 만들고, 세분화된 운세 카테고리로 자연스럽게 유료 결제로 이어집니다.

**포스텔러**: 세련되고 트렌디한 미니멀 UI(파스텔·그라데이션), 생년월일시 입력 온보딩이 매우 매끄럽고, 결과 카드가 SNS 공유에 최적화되어 있어 MZ 세대에게 "예쁘다"는 평가를 받습니다.

### Transferable UX Patterns

**Navigation Patterns:**
- 웹툰/카카오페이지의 "다음으로 자연스럽게 이어지는" 넘김 UX → 캐릭터 세계관 탭에서 "다른 캐릭터 구경하기"나 친구 궁합 순위 넘겨보기에 적용 가능
- 점신의 카드 기반 탭 구조 → 하단 탭바(사주 등록 / 캐릭터 세계관) 설계에 참고

**Interaction Patterns:**
- 포스텔러의 매끄러운 생년월일시 온보딩 플로우 → saju 입력 폼 설계에 직접 참고
- 도령앱의 "최소 입력 → 즉시 결과" 흐름 → 온보딩 마찰 최소화 원칙에 그대로 부합

**Visual Patterns:**
- 웹툰의 캐릭터 중심 몰입형 커버아트 → 캐릭터 리빌 비주얼의 임팩트에 직접 연결
- 포스텔러의 SNS 공유 최적화 카드 디자인 → saju 결과 카드가 지향해야 할 완성도의 기준점

### Anti-Patterns to Avoid

- **카카오페이지식 시간 잠금/결제 타이머**: MVP 단계에서는 불필요한 복잡도 — 유료 심화 사주는 이후 단계로 미룹니다.
- **점신식 과도한 카테고리 세분화**: 수십 개의 운세 메뉴는 사용자를 압도할 수 있어, saju는 핵심 기능(캐릭터+궁합)에만 집중합니다.
- **잦은 푸시 알림으로 재방문 강요**: 운세 앱 업계의 흔한 패턴이지만, "강요하지 않는다"는 saju의 감성 원칙과 정면으로 배치되므로 명시적으로 피합니다.

### Design Inspiration Strategy

**What to Adopt:**
- 포스텔러의 매끄러운 온보딩 + SNS 공유 최적화 카드 — 핵심 바이럴 루프와 직결되기 때문
- 웹툰의 캐릭터 중심 비주얼 임팩트 — 리빌 모먼트의 경외감을 만드는 데 핵심이기 때문

**What to Adapt:**
- 점신의 카드 UI 언어는 차용하되, 귀여운 톤 대신 다크 에픽 톤으로 재해석
- 웹툰의 "다음 화" 넘김 패턴은 "세계관 탐색"으로 순화해 강제성 없이 재방문 훅으로 활용

**What to Avoid:**
- 카카오페이지식 결제 타이머, 점신식 과도한 메뉴 분화, 푸시 알림 기반 재방문 강요 — 모두 saju의 "단발성이어도 괜찮다"는 원칙과 충돌

## Design System Foundation

### 1.1 Design System Choice

**Tailwind CSS + shadcn/ui** (테마 가능한 시스템)를 기반으로 합니다. Tailwind의 유틸리티 클래스로 빠르게 스타일링하고, shadcn/ui의 접근성 갖춘 헤드리스 컴포넌트(버튼, 인풋 등 기본 요소)를 다크 에픽 톤으로 테마 커스터마이징해서 사용합니다.

### Rationale for Selection

- **속도**: 1주일 MVP 스코프에서 기성 컴포넌트를 처음부터 만들 시간이 없습니다. Tailwind는 별도 학습곡선 없이 바로 빠르게 조립할 수 있습니다.
- **시각적 독자성 확보**: 기성 시스템(Material 등)은 saju의 다크 에픽·웹소설 감성과 충돌합니다. Tailwind는 디자인 의견이 강요되지 않아, 별빛 배경·금박 프레임·캐릭터 리빌 카드 같은 커스텀 비주얼을 자유롭게 구현할 수 있습니다.
- **접근성 기본값**: shadcn/ui는 헤드리스 컴포넌트라 버튼, 인풋 같은 기본 요소의 접근성(포커스 상태, 키보드 내비게이션)을 처음부터 챙길 수 있어, 촉박한 일정에서도 품질을 잃지 않습니다.

### Implementation Approach

- 공유 요소(버튼, 인풋, 칩, 카드 껍데기)는 shadcn/ui 프리미티브를 다크 에픽 컬러 토큰으로 테마 커스터마이징
- 캐릭터 리빌 카드, 절대자 선언 연출, 궁합 순위 카드 등 saju만의 독자적인 비주얼은 완전 커스텀 컴포넌트로 별도 제작
- Tailwind 설정에 다크 에픽 팔레트(딥 인디고/플럼 배경, 골드 액센트)를 디자인 토큰으로 등록해 전체 화면에서 일관되게 사용

### Customization Strategy

- 색상: 딥 인디고/플럼 배경 + 골드 액센트를 Tailwind 커스텀 컬러로 등록
- 타이포그래피: 제목용 세리프(드라마틱한 선언 톤) + 본문/UI용 산세리프 조합을 Tailwind 폰트 패밀리로 설정
- 컴포넌트: shadcn/ui 기본 컴포넌트는 그대로 쓰되, 캐릭터 카드·프레임 장식·순위 리스트 등은 프로젝트 전용 컴포넌트로 신규 제작
